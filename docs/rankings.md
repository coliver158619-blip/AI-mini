# 充电榜示例

入口：更多玩法 → 打榜；页面地址 `/#/rankings`。沿用昵称小屋登录，两个榜单共用粉紫色页面与搜索入口。

- **明星榜**：选择一位明星，展示其与上榜用户的累计充电值，按充电值降序取前 1000 名。前三名单独展示；每批 50 人，点击加载更多，达到 1000 后停止。底部显示当前用户的位置及充电值；榜外显示距上榜的差值。
- **个人榜**：按当前用户与各明星的累计充电值降序取前 100 名。搜索命中后滚动并高亮真实排名，不因搜索重新编号。明星在第 100 名以外时显示榜外提示，不插入前 100 名列表。
- 支持明星中文名称与部分常用拼音/英文缩写（如 `lyn`、`zsh`、`jay`）搜索；空结果、接口失败和分页失败均有对应反馈。
- 标题与底部信息固定，榜单单独滚动，安全区与迷你播放器有留白；短横屏将控制区与榜单并排。

## 数据

`backend/rankings.py` 为稳定生成的虚构示例：128 位明星、1199 名虚构用户和当前用户。明星榜与个人榜使用同一份充电值规则，同一小屋重启后数值及排序保持一致。不同小屋的个人榜按账号 ID 独立生成。均标注“示例榜单”，不写入或改变真实的能量、装扮、聊天和陪伴空间数据。

这是只读示例，当前未接入真实充电值累计、打榜赠礼、结算或奖品。用户头像为生成昵称的首字。128 位明星使用公开音乐平台的真实歌手头像，照片本地保存在 `public/assets/star-portraits/`，来源记录在 `sources.json`。页面按人脸位置进行圆形特写取景，乐队保留合照；图片加载失败时回退到姓名首字。

## 接口

接口都受既有昵称登录保护，返回 `isDemo: true`。界面统一称为“充电值”；JSON 数值字段沿用 `intimacy`，保持已有接口兼容。

| GET 接口 | 用途 |
| --- | --- |
| `/api/rankings/stars?q=张韶涵` | 搜索可切换的明星；不传 q 返回目录 |
| `/api/rankings/star?starId=lyn&offset=0&limit=50` | 某明星前 1000 用户及当前用户位置；返回 `nextOffset`，每次最多 100 人 |
| `/api/rankings/personal` | 当前用户与明星的前 100 名 |
| `/api/rankings/personal/search?q=周杰伦` | 全明星范围内查找个人排名，返回原始 rank、intimacy 与 inTop100 |

明星 ID：刘宇宁为 `lyn`，张韶涵为 `zsh`，其他为稳定的 `star-NNN`，由明星目录查询。重复参数、无效明星和超限分页返回 400。

```sh
npx playwright test -c playwright.rankings.config.ts
```

覆盖边界及分页、排序去重、两类榜单数值一致、搜索定位、榜外提示、账号隔离、只读性、重启稳定性、失败重试以及窄屏/安全区/横屏与播放器适配。
