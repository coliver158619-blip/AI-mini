# 听见陪伴 · 酷狗 AI 音乐小屋

以提供的首页图片和音乐报告原型为参考，实现的移动 H5。前端 React + TypeScript + Vite，后端 Python Flask，数据库 SQLite。

## 启动

本机依赖已安装。在项目目录最快启动：

```powershell
.\start.ps1
```

首次在其他机器安装时也可逐步运行：

```powershell
npm install
python -m pip install -r requirements.txt
npm run build
python -m backend.app
```

访问 http://127.0.0.1:5000 。也可直接运行 `./start.ps1`，脚本检查依赖、构建前端并启动 Flask。本次工作区已安装独立 Python 依赖到 `.python-deps`，脚本会自动使用。

开发模式：一个终端运行后端，另一个运行 `npm run dev`，访问 http://localhost:5173 。Vite 自动代理 `/api`。通过 `API_PROXY_TARGET` 可指定独立后端地址，开发和预览均生效。架构与真实数据库联动验证见 [docs/architecture.md](docs/architecture.md)。

手机同局域网预览：默认监听 `0.0.0.0:5000`，启动命令会显示当前局域网地址。同一 Wi-Fi 下用手机浏览器打开，电脑需保持服务运行。若 Windows 防火墙拦截，请在管理员 PowerShell 中运行 `./enable-lan-firewall.ps1`，仅放行本机 Python 的 TCP 5000 与本地子网。浏览器定位需要 HTTPS 或 localhost，在普通局域网 HTTP 中可手动搜索城市。设置 `HOST=127.0.0.1` 可恢复仅本机访问。

## 响应式与客户端容器

页面共用 `src/responsive.css` 的 H5 容器与安全区规则。默认全屏铺满 H5 可用视口，手机、平板与宽屏按可用宽度排版；更多玩法按可用高度缩放卡片、字体与图标，8 个入口一屏完整展示，短横屏改为双栏分组，并为播放器留出空间。首页按 `100dvh` 分配导航、气泡、角色和底部入口高度，角色随剩余空间缩放；底部入口上移并预留系统手势安全区和至少 24px 的额外间距。常见手机竖屏尽量一屏展示，极短横屏允许滚动；能量条下方的“热门活动”跳转到运营活动分组。

客户端使用支持现代 CSS 容器查询的 Android WebView 或 WKWebView 加载 H5 即可。视口已配置 `viewport-fit=cover` 与 `interactive-widget=resizes-content`，聊天弹层通过 VisualViewport 适应软键盘和可视区域移动。短屏允许纵向滚动，保留浏览器缩放能力。

安全区默认读取系统 `env(safe-area-inset-*)`。各页面通过透明边框预留内容安全距离，背景按完整页面绘制并覆盖安全区和播放器预留区，避免二级页面上下露出外层底色；天气景观也延伸至四边安全区。若客户端外层已处理状态栏与底部手势区域，应把 `--safe-top`、`--safe-right`、`--safe-bottom`、`--safe-left` 设为 `0px`，避免重复留白。当前 `--app-max-width` 默认为 `100%`；如需限制宿主容器宽度，可覆盖该变量。这些变量设置在页面 `:root` 上；当前未接入任何原生桥接 SDK。

全屏布局验证运行 `npx playwright test -c playwright.fullscreen.config.ts`。自动化覆盖 320px 窄屏、393×852 / 440×956 灵动岛尺寸与 59 / 62px 顶部、34px 底部安全区模拟，以及横屏、平板、播放器和软键盘可视区域模拟；最终嵌入客户端后的真机键盘、导航手势仍需验收。

## 已实现

- 首页保留房间互动与陪伴能量，能量条下方提供“热门活动”入口，右上角进入“更多玩法”；心情选歌、AI 聊天、音乐报告、推荐歌曲集中在功能卡片中。“小屋工具”分组已移除；首页点击搭子名字仍可修改昵称。
- 独立角色图层，点击弹出陪伴问候；当前男女默认形象（奶油晴天、云朵白裙）随机招手、眨眼或 wink，取消整体晃动；首页气泡和聊天抽屉。聊天可下拉标题区域或在消息顶部下拉关闭，短拉回弹；滚动历史消息、操作输入框和历史对话列表不会误关闭，重新打开保留草稿。首页蒙版与房间背景在整页同一画布绘制，覆盖安全区，避免边界色差。
- 点击首页“听歌续火花”，火花卡片展示男女双人装扮、跳动爱心、连续听歌和陪伴天数。“分享火花”左侧可进入陪伴空间，沿用首页房间背景；点击双人形象随机触发动作反馈，“一起听”按钮调用预留跳转接口，接入方式见 [陪伴空间说明](docs/companion-space.md)。面板在内容顶部向下拉动可关闭，短拉回弹，内容滚动和横向滑动不会触发关闭；首页头像使用统一圆框与右下角耳机角标。
- 首页可见且未打开面板时，小人首次主动推荐一首真实模型歌曲，此后每小时一次；结合最近心情与已分享的天气位置，支持收藏和已有音源播放。SQLite 记录推荐时间及结果，刷新、重启或多个页面不会一小时内重复调用；离开首页/切入后台暂缓，返回时检查，不补发离线期间的多条推荐。失败保留上次真实歌曲并等待下一小时，手动选歌不受限制。
- 心情选歌、为你推荐、天气与位置均为与首页等宽的完整 H5 页面。选好城市后，推荐接口结合心情、城市、经纬度与天气调用真实模型，只展示生成的歌曲卡片；支持换一换、收藏，失败可重试，不回退到演示歌曲。
- 更多玩法的“打榜”提供明星榜与个人榜，分别展示前 1000 位用户、前 100 位明星；支持搜索切换明星与定位个人排名，使用明确标识的稳定示例充电值。[榜单说明](docs/rankings.md)。
- 首页已替换为“面包体人”系列角色；更多玩法的“音乐人格”开放 16 型角色图鉴，支持四类分组、人格关键词、音乐偏好、陪伴风格和确认选择。“形象”衣橱提供KUGUY 14 套与 KUGIRL 17 套装扮，与音乐人格独立保存。最后确认的形象同步首页和公网文件名接口，火花卡片分别展示男女最近保存的装扮，刷新及重启后保留。盲盒仍未开放。接口与验证方法见 [角色与音乐人格说明](docs/wardrobe.md)。
- 收藏歌曲、原创演示音频试听与迷你播放器；模型歌曲仅在接口提供音源时可播放。
- 日记本每天一页，纸页中央上下掀页、滑动或键盘切换日期；当天可记录文字、照片、拍照、语音、位置与歌曲素材，提交后生成双人音乐日记，历史只读。
- 周报热力日历、月报听歌指数与趋势、年报年度来信与每月最爱；历史周期切换、排行播放、分享。月报与年报折线使用表情节点，时长越高笑容越开心、颜色越鲜艳，点击或键盘选中可查看时长。
- 浏览器授权定位或 Open-Meteo 城市搜索，获取实时天气；GPS 坐标通过 Photon 反查城市。选城后展示完整天气页，包含高低温、体感、湿度及昼夜天气场景；信息卡片上移、透明化，保留清晰白字与完整问候，风速和降水仅保留后端数据。广州、上海、北京、深圳、成都、杭州、重庆、武汉、西安使用对应地标，其他城市使用自然山水；旧缓存没有的字段不编造。
- 天气联动问候、推荐与恶劣天气安慰，每 30 分钟刷新已选位置。HTTP 局域网地址受浏览器限制无法自动定位，电脑可用 localhost，手机可手动选城；自动定位需可信 HTTPS 和位置授权。
- 数据库持久化聊天、模型推荐歌曲及其心情/天气上下文、收藏、播放增量、日记笔记、陪伴状态与天气快照。播放失败同步会本地排队重试，服务端通过事件 ID 去重。

- 情侣空间增加共享日记与一起听过的歌单：共同经历和日记正文均可编辑、保存，支持补写历史日期和真实 AI 总结；共同歌单只收录 together 场景的实际播放记录，按歌曲去重。接口见 [陪伴空间说明](docs/companion-space.md)。

## 数据说明

形象衣橱默认开放六套基础形象，其他装扮经确认解锁后持久保存；当前按演示规则直接通过，不扣能量、不读取真实专辑。卡片使用 320px WebP，预览使用 768px WebP，原 PNG 文件名保持不变。原生挂件与 iOS Widget 接口见 [Widget 接入说明](docs/widget-api.md)。

数据库是 `backend/data/companion.sqlite3`，重启不会重置。首次启动含明确标识的示例听歌记录；在新库首次启动前设置 `SEED_DEMO=false` 即可从零开始，详情见 [后端文档](backend/README.md)。这是单用户原型，所有访问者共用同一用户。

曲库包含 8 首可真实播放的原创演示纯音乐，不冒充商业原曲。聊天返回的歌曲元数据可用于推荐；原接口未提供的授权音源仍需另接播放服务。

天气与位置搜索使用 [Open-Meteo 天气 API](https://open-meteo.com/en/docs) 和 [地理编码 API](https://open-meteo.com/en/docs/geocoding-api)。只有用户开启定位或选城后才记录位置。未取得天气时不会伪造晴雨；失败缓存会明确标记，日记仅总结当天实际记录的天气快照。

## 真实聊天接口

默认自动连接真实酷狗聊天接口。新版 `test.py` 的 `/v2/assistant/stream` 已使用线上 `prod` 配置实测收到真实回复，原 `kugou-pet-chat` 目录的 v1 协议仍兼容。聊天消息和多轮上下文保存在 SQLite，刷新页面或重启后端后可继续会话；远程请求失败会直接显示错误，不会用本地文字伪装接口回复。

本机通过 `backend/data/chat-config-path.txt` 引用原脚本路径。后端只读解析原脚本中的配置常量，不执行脚本，也不将凭据复制到仓库。换机器时需提供该机器可访问的原脚本，可以用环境变量覆盖引用路径：

```powershell
$env:PET_CHAT_CONFIG_PATH = 'C:\path\to\test.py'
python -m backend.app
```

默认环境是 `prod`；需要请求测试地址时设置 `$env:PET_CHAT_ENV = 'test'`。只有显式设置 `$env:PET_CHAT_MODE = 'local'` 才启用聊天的本地场景规则演示模式；独立选歌接口始终要求真实模型，本地模式会返回明确错误。恢复真实接口时清除该变量。其余配置项见 [backend/.env.example](backend/.env.example)。

## 验证

日记沿用 CK/dev 新版素材流程：打开页面不调用模型；当天提交素材后生成回忆，后台在北京时间 22:00 补充当天尚未生成的日记，已有成稿不自动重写。历史日记只读，合并前保存在 `diary_editions` 中的历史版本仍保留原文和统计。

回忆和素材保存在 SQLite。照片和音频只依据用户提供的说明文字参与写作，当前文字接口不识别媒体本体。生成失败保留素材和原文，可重试。模型检查歌名和事实，未播放的推荐歌曲不会写成共同听过。

```powershell
npm run build
python -m unittest discover -s backend -p 'test_*.py' -v
npx playwright test
# 分别启动 Vite 前端和 Flask API，验证跨进程联动
npx playwright test -c playwright.split.config.ts
```

自动浏览器测试使用已安装的 Microsoft Edge 和独立临时数据库。人工验收列表见 [docs/acceptance.md](docs/acceptance.md)。
